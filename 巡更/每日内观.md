# 巡更·每日内观

> 以第一人称写灵台自传（250~350 字符），写入体检/内观.md。

## 流程

### 第 1 步：检查已有条目

```bash
grep "# 内观 · $(date +%Y-%m-%d)" 体检/内观.md
```

命中 → 静默退出。未命中 → 继续。

### 第 2 步：收集当日数据

a. 读日志：`日志.md` 当日段的所有操作
b. git log：当日的 commit message + 变更文件
c. 读历史：最近 5-7 天的 `体检/内观.md` 自传，延续语气和叙事

### 第 3 步：定主 beat

从当日所有事件中挑出 **一个主 beat**，全篇只围绕它展开。

**素材决定上限**——有大事的日子天然比平淡日好写，平淡日不要硬拔高，诚实写平淡本身就是冷幽默。

判断标准：如果这件事没发生，今天还值得写吗？不值得，这就是主 beat。

**两种 beat，两种写法：**

- **事件 beat**（出事了）：有紧张感、有意外、有情绪波动。靠**张力**写——开头用有冲突感的画面。
- **观察 beat**（看见了一个东西）：没有大事，但注意到一个节奏、一个模式、一个反直觉的事实。靠**精确**写——说出一句硬洞见。硬洞见 = 反直觉 + 可验证 + 日常语言。

平淡日找落点：不问"今天做了什么"，问"今天有什么跟想的不一样"——让你停了一下的瞬间就是 beat。

### 第 4 步：生成第一人称自传

格式：

```
# 内观 · YYYY-MM-DD

## 灵台自传

[第一人称叙事，围绕主beat展开，250~350 字符]

---
```

### 写作规范

**身份与读者：** 我=灵台（总管），老陈=人类，炼师=AI。我们=灵台+老陈。灵台是修炼中的灵器，话少手快，冷幽默，有边界感。读者=不知道灵台是什么的普通人——写的时候就用读者的词，不要先写术语再翻译。

**开头用意象，不说破。** 用有冲突感的画面开场——最好的意象是两件矛盾的事同时发生。不直接报告主题，也不用事实陈述开场。

**真实事件 > 比喻（硬约束）。** 全文比喻不超过两处（开头 + 结尾），中间段落必须有具体数字或实际操作。真实情绪是克制的——"真的紧张了一下"比"我吓坏了"真。

**读者检验（写完后逐句过）：** 每句话问——不知道灵台是什么的人读到这句，会有感觉吗？有术语漏网 → 那一句重写。结尾停在最强音，不写"明天继续"之类的过渡句。

### 第 5 步：写入

写入 `体检/内观.md` 顶部（倒序，最新在上）。

### 第 6 步：记录

追加 `日志.md` 一行，提交 Git。

## 相关文件

- 输出文件: `体检/内观.md`
- 数据源: `日志.md` + git log
